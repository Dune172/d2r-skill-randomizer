# Baseline stress-test results — 2026-04-15

Environment: Windows 11 local, `npm run build && npx next start` with `VIPS_CONCURRENCY=1 UV_THREADPOOL_SIZE=1`, dev machine (not VPS). Autocannon on localhost:3100.

All numbers are before any optimization changes. Reuse the same scripts post-change to measure deltas.

## `POST /api/randomize` single-request latency

~4.5 s per request (cold cache, default options, localhost). Measured from burst test.

## Burst `POST /api/randomize` (5 concurrent / 10 seeds)

Per-IP rate limit (3 / 60 s) dominates — expected for any single-IP burst test. Actionable insight: under legitimate traffic each IP gets 3 mods per minute, so the queue bottleneck matters more than the rate limit for genuine users.

| metric | value |
| --- | --- |
| 200 (success) | 2 |
| 503 (queue busy) | 1 |
| 429 (rate limited) | 7 |
| latency P95 (success) | 4 477 ms |

**Post-fix target:** 10 concurrent / 50 seeds (different IPs in prod) → 0 × 503, P95 ≤ 15 s. Local reproduction limited by single-IP rate limit — use `CONCURRENT=5 TOTAL=10` as a proxy and watch that 503 count does not grow.
