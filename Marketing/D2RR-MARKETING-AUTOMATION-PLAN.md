# D2RR Marketing Automation Plan

**Product:** [d2rrandomizer.com](https://d2rrandomizer.com) — Diablo 2: Resurrected skill randomizer with seeded shareable runs, 14 mutations, and a biweekly mutation challenge (flips every other Monday, 00:00 LA time).
**Channels:** Reddit + Discord (community), Twitter/X, YouTube/Twitch creator outreach.
**Current state:** Occasional manual posts. The app already auto-posts each new challenge to Discord (webhook, 9 AM LA on rotation Monday, with OG card PNG) — automation builds outward from that.
**Method:** Applies the frameworks in `CLAUDE-MARKETING-MASTER-PLAN.md` (five ingredients, skills/connectors/scheduled tasks, validation protocol) and `CLAUDE-CODE-ADS-MASTER-PLAN.md` (build tools for mechanical constraints, encode standards as skills, human review before publish).

---

## 1. The Content Engine: the Challenge Cycle

The biweekly challenge rotation is the natural heartbeat — recurring, deterministic, and already half-automated. Every cycle produces the same raw material (challenge number, theme name, active mutations, seed, leaderboard results), so every cycle can produce the same content package. This scores 5/5 on the five-ingredients checklist: multiple inputs (registry, leaderboard, OG card), clear deliverables (posts), repeats forever, "good" is obvious in 10 seconds, and the middle is boring.

**Per-cycle content package (generated by one skill, see §3):**

1. Reddit post for r/Diablo2 / r/Diablo (challenge announcement: theme, mutations, seed, link) — drafted, posted manually after review
2. X thread: announcement post + a "mutation spotlight" explaining what the combo does to builds
3. Discord: already automated in-app; add an end-of-cycle leaderboard recap post
4. End-of-cycle recap: top leaderboard runs, total generations delta (from `/api/health` counter), teaser for the next theme

## 2. Foundation: One-Time Setup (Week 1)

**Connectors.** Wire up before building anything: Reddit (via MCP registry if available, otherwise Chrome), X/Twitter, Gmail (creator outreach), and the site itself (`/api/health`, challenge/archive pages — no connector needed, just fetch).

**Brand voice skill (`d2rr-voice`).** The shared standards layer every other skill loads — playbook rule: company-wide assets belong in skills. Contents: tone (player-to-player, no corporate speak; D2 community vocabulary — "HC", "SSF", "/players 8"), the three product facts that must always be right (offline-safe / won't flag Battle.net; same seed = same run, shareable; mutations are opt-in modifiers), things never to claim (Blizzard affiliation, online play safety), and per-channel format rules (Reddit: no link-spam tone, lead with the run story; X: 1–2 posts, card image attached).

**Asset inventory.** The OG challenge card renderer (`src/lib/og/challengeCard.tsx`) and mutation card images (`public/mutations/*.webp`) already exist — reuse them as the visual for every channel rather than generating new creative.

## 3. Skills to Build (Weeks 1–3)

Layered per the playbook: methodology / conventions / process kept separate.

**`d2rr-challenge-package` (process skill).** Input: challenge number (or "current"). Reads the live challenge page + mutation registry for theme and mutations, loads `d2rr-voice`, outputs one markdown file containing all per-cycle posts from §1, each with a **reasoning line** (why this angle, which mutation interaction it highlights) as the audit trail. Nothing auto-posts on first runs — present, review, then publish.

**`d2rr-recap` (process skill).** Input: just-ended challenge number. Pulls leaderboard results and the generation counter, writes the recap posts, flags anything anomalous (e.g., counter flat — worth investigating before celebrating).

**`d2rr-creator-outreach` (methodology + process).**
- *Methodology layer:* what makes a good fit (D2R streamers/YouTubers who do challenge runs, SSF, hardcore, or mod content; 1k–200k followers — small enough to reply, big enough to matter), what doesn't (pure trading/botting channels), and the pitch angle: a randomizer run is *content format*, not a product plug — offer a custom seed or a named mutation challenge for their community.
- *Process layer:* search YouTube/Twitch for recent D2R challenge-run content → build a CSV with channel, size, recent relevant video, fit reasoning column, suggested personalized hook → human reviews → draft (not send) Gmail outreach for approved rows. Outreach never auto-sends.

**`d2rr-community-pulse` (process skill).** Scan r/Diablo2, r/diablo, and target Discords for mentions of "randomizer", "D2RR", or challenge-run discussion. Output: mentions worth replying to (with suggested reply), feature requests/bug reports, and content ideas from what runs people are sharing.

## 4. Scheduled Tasks (Week 3–4, after skills prove out)

| Task | Schedule | What it does |
|---|---|---|
| Challenge package | Every other Monday, 6 AM (rotation day) | Runs `d2rr-challenge-package`; drafts waiting for review before the 9 AM Discord auto-post goes out, so all channels land the same morning |
| Cycle recap | Every other Sunday evening (cycle end) | Runs `d2rr-recap`; recap ready to post Monday alongside the new announcement |
| Community pulse | Mon/Thu mornings | Runs `d2rr-community-pulse`; 5-minute skim, reply where worthwhile |
| Creator pipeline | Monthly | Runs `d2rr-creator-outreach`; review CSV, approve drafts |
| Health glance | Weekly | Generation counter trend + uptime from `/api/health`; one-line TLDR, flag drops |

Per the playbook: schedule for *before* you sit down, lead every output with a TLDR, same template every run.

## 5. Validation Protocol

- **First runs supervised.** Run each skill interactively 2–3 cycles before scheduling it. Check every product claim against the README/site.
- **Audit trails everywhere.** Reasoning columns in the outreach CSV; reasoning lines under each drafted post.
- **Human gate on everything outward-facing.** Posts, replies, and emails are always drafted for approval — never auto-published. (The in-app Discord webhook is the one exception; it's deterministic template output.)
- **Corrections feed the skill.** Same fix twice → update the skill, not the output.

## 6. Rollout Summary

| Phase | When | Milestone |
|---|---|---|
| 1 — Connect | Week 1 | Connectors live; `d2rr-voice` skill written (dictate it) |
| 2 — First win | Weeks 1–2 | `d2rr-challenge-package` run interactively for one full cycle |
| 3 — Encode | Weeks 2–3 | Recap, outreach, and pulse skills built and validated |
| 4 — Automate | Weeks 3–4 | Scheduled tasks on; review-and-post is the only manual step |
| 5 — Scale | Ongoing | Track time-per-cycle and generation counter; fold learnings into skills weekly |

**Success measures:** marketing time per cycle (target: under 30 min of review/posting), generation counter growth cycle-over-cycle, challenge leaderboard participation, creator videos landed per quarter. Baseline at automation start (2026-06-11): **4,787 total generations**.
